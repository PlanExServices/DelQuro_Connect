# DelQuro Connect store requirements audit

Checked November 18, 2026 against official Apple and Google guidance. The current release scope is a staff-only beta of an invite-based veterinary workplace app. Evidence comes from the candidate source, isolated synthetic tests and local unsigned or development-signed builds. Approval, the organization’s console settings, signing and the live pilot service require separate verification.

## What the current guidance adds

- Apple’s upload floor is Xcode 26 and iOS 26 SDK, with a separate iOS 13 minimum deployment target since September 9, 2026. Apple has announced iOS 27 SDK and iOS 15 deployment minimums starting April 2027. The October 2026 review update broadened user-generated content guidance and added rules for creative assets and hidden, dormant or undocumented functionality. The current screenshot specifications identify the Dynamic Island medium slot and the future iPhone Duo requirement. [Apple upload requirements](https://developer.apple.com/news/upcoming-requirements/) · [April 2027 requirements](https://developer.apple.com/app-store/submitting/) · [October guideline update](https://developer.apple.com/news/?id=92th7e5i) · [Screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications)
- Google Play’s API 36 submission floor for new phone apps and updates took effect August 31, 2026. The published extension ended November 1. Google’s current guide requires 16 KB compatibility for API 35+ apps and specifies February 1, 2027 for blocking nonconforming updates. Verify ZIP and ELF alignment, GNU_RELRO and real launch behavior on a 16 KB system. Play says all Play package names must be registered for Android developer verification starting September 30, 2026. Google-generated Play signing keys for new apps can use Google’s documented hybrid signing, with a separate app bundle upload key. [Target API](https://support.google.com/googleplay/android-developer/answer/11926878) · [16 KB requirements](https://developer.android.com/guide/practices/page-sizes) · [Developer verification](https://support.google.com/googleplay/android-developer/answer/16984799) · [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756)

## Security and pilot release gates

- Pilot with an isolated workspace and test accounts. On November 19, Coolify showed only the production Connect application and its MongoDB. The production HTTPS readiness endpoint returned HTTP 200. An isolated pilot still needs its own deployment and data. Assign a support contact and a moderation and deletion owner before entering staff data.
- Keep team-generated files out of public URLs. The candidate uses authenticated attachment headers and carries web chat credentials in the handshake, with password-change revocation for browser, mobile and live chat. Invitation recipients and staff data visibility are checked server-side.
- The November 18 frontend scan reported 31 entries, including 14 high, through the retired Create React App build and test chain. The Vite lockfile clears the high findings and updates the remaining CSS parser dependency. Both Python Dockerfiles remove unused setuptools and wheel after dependency installation to address the vendored packages found by the previous production scan. Verify the rebuilt runtime images in CI and rescan the deployed image after release.
- Historical public tests contained plaintext fixture credentials paired with an administrator email. The candidate reads isolated test-account credentials from `CONNECT_TEST_ADMIN_EMAIL` and `CONNECT_TEST_ADMIN_PASSWORD`, with corresponding variables for staff and managers where needed. Treat the historical administrator password as exposed and rotate it if still used.
- Verify the actual store-signed app binaries and deployment before recruiting testers. Source and dependency review cannot verify the final build signature, production TLS and access controls, malware screening operations or App Review outcomes.
